## Actual intended architecture
One QBCore `ps-mdt` resource with a shared backend and **five original interfaces** SADLE (state LEO oversight), SADOJ (independent courts), SAFR (fire), SAMS (hospital/medical), SAGOV (jurisdictional government); **SADOT later sixth**, deliberately disabled until qualified permit/role enforcement. Use authoritative `planning-reference/jobs.lua`. Framework type `fire` remains fire and `ems` remains medical. UI selection must not change the actual QBCore job. Departments own ordinary records, rosters, SOPs and training; only specifically approved authorized state actors receive oversight, not every boss. DOJ judiciary and SADLE AG prosecutor authority are separate. Existing LEO/DOJ systems and histories must be preserved.

## Mandatory acceptance matrix — test before each stage sign-off
- **SADLE/LEO**: LSPD, BCSO, FIB, SADLE; normal officer/department boss/AG/explicit SADLE investigator; department-owned report and roster, explicit statewide oversight and cross-agency report grants, deny unauthorized changes.
- **SADOJ**: clerk/prosecutor/assigned defense/AG-as-prosecutor/judges; separate judicial adjudication, read vs discovery grants, permanent court case and hearing closure, protected evidence access.
- **SAFR**: state SAFR versus LSFD/LSCFD/BCFD; individual employer roster and management, fire run report, fire training, cross-department sharing only if authorized.
- **SAMS**: Pillbox/Sandy/Paleto/Parsons; employer roster, medical chart privacy and hospital training, no automatic fire or police access to patient charts.
- **SAGOV**: state/Blaine County/Los Santos County/Los Santos City hierarchy, government role/grade personnel, isolation of unpublished drafts and scoped state oversight, no criminal-justice privilege.
- **SADOT**: must remain denied for a generic mechanic until roles/permit checks exist. Later verify licensed tow operations, 511 and record journaling, integrated existing reports, no unrelated garage dependency.
- **Regression/security**: duty/grade/job/character switches during DB yields, multiple concurrent editors, direct-ID/list/search/analytics parity, owner retention on updates, unknown/ambiguous IA routing, existing historical records, migration rollback.
- **Artifacts for sign-off**: exact source ref/commit; complete test logs (Lua/Node/SQL); web build output and deployment provenance; human FiveM/F8 observations. A green source-string scan alone is never sign-off.
